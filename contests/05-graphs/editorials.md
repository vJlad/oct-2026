# 05. Графы и пути — разборы

## A. Build the Non-Cactus (104848F)

Нужен связный граф с `n` вершинами, не являющийся кактусом, с минимумом
рёбер.

«Не кактус» — значит есть два простых цикла, делящих ребро. Минимальный
такой граф — ромб: треугольник `1-2-3-1` и вершина `4` с рёбрами `1-4`
и `2-4`. Два цикла (`1-2-3` и `1-2-4`) делят ребро `1-2`, рёбер 5
на 4 вершинах.

Остальные вершины `5..n` вешаем цепочкой на `4` — каждая добавляет одно
ребро и не создаёт новых циклов. Итого `n + 1` ребро, это минимум
(меньше нельзя: 4 вершины и 4 ребра — это либо дерево, либо один цикл).

Для `n = 3` ответа нет: треугольник — кактус, а других графов на 3 вершинах
с циклами не бывает.

Сложность `O(n)`. Ловушка: строить «восьмёрку» (два треугольника с общей
вершиной) — это кактус.

## B. The Two Routes (601A)

Ключ: между любой парой городов есть либо железная дорога, либо шоссе,
но не обе. Значит ровно у одного транспорта есть прямое ребро `1 → n`.

Этот транспорт доезжает за 1 час и дальше ждёт в городе `n` (ждать можно,
конфликт «приехали одновременно» касается только промежуточных городов).
Второй транспорт едет по своему графу, и его время и есть ответ:

- если железная дорога `1–n` есть, то ответ — `BFS` в дополнении графа
  (граф шоссе);
- иначе ответ — `BFS` по железным дорогам.

Если второй транспорт не может добраться — `-1`.

Сложность `O(n²)` на построение дополнения (при `n ≤ 400` это нормально).
Ловушка: моделировать одновременное движение по времени — при таком
раскладе это не нужно.

## C. Edgy Trees (1139C)

Последовательность «плохая», если путь между соседними вершинами ни разу
не проходит по чёрному ребру — то есть все `k` вершин лежат в одной
компоненте связности красных рёбер.

Собираем компоненты по красным рёбрам через DSU, считаем размеры `s_i`.
Число плохих — `Σ s_i^k`, значит

```
answer = n^k − Σ s_i^k   (mod 1e9+7)
```

Сложность `O(n α(n) + n log k)`. Ловушка: вычитать `Σ s^k` из `n^k`
и не учесть, что изолированные вершины — тоже компоненты размера 1.

## D. Fare (104805C)

Граф — дерево, путь единственный, проходит через `LCA(u, v)`.

Подвешиваем за 1 и считаем `pref[v]` — произведение весов рёбер на пути
от корня до `v`. Тогда произведение на пути:

```
pref[u] · pref[v] · inv(pref[lca])²
```

Все веса `w < 1e9+7`, поэтому обратный элемент существует; считаем его
через быстровозведение в степень `mod − 2`.

Сложность `O((n + q) log n)`. Ловушка: делить целочисленно вместо
умножения на обратный элемент; и брать `lca` вместо его `pref`
в квадрате.

## E. Just the Last Digit (104874J)

`a[i][j]` — число путей `i → j` (по модулю 10) в исходном DAG
(все рёбра идут из меньшего номера в больший).

Идём `i` от `n` до `1`, поддерживая `cnt[i][j]` — число путей `i → j`
по уже восстановленным рёбрам. Для `j` от `i+1` до `n`:

- если `cnt[i][j] != a[i][j]`, значит ребро `i → j` существует: добавляем
  его и прибавляем к строке `i` строку `j` (все пути из `j`) плюс единицу
  в позицию `j` (сам путь `i → j`);
- иначе ребра нет, ничего не делаем.

Почему это корректно: строки `j > i` уже посчитаны окончательно, а любой
путь `i → k` раскладывается по первому ребру `i → j`, поэтому, восстановив
рёбра из `i`, мы получаем ровно `a[i][*]`.

Сложность `O(n³)` (при `n = 500` это `1.25·10^8`). Ловушка: обрабатывать
`i` по возрастанию — тогда `cnt` ещё не готов.

## F. Equidistant (104874E)

Пусть `x` равноудалена от всех отмеченных, расстояние `d`. Возьмём две
отмеченные вершины `u, v` на максимальном расстоянии (диаметр множества).
Тогда `x` лежит на «середине» пути `u–v`: множество точек, равноудалённых
от `u` и `v`, в дереве — это середина пути (вершина при чётном расстоянии)
и поддеревья, висящие в ней.

Отсюда алгоритм:

1. Находим диаметр множества отмеченных (два обхода/BFS от произвольной
   отмеченной, затем от самой дальней).
2. Если длина диаметра нечётная — ответа нет.
3. Берём середину `p` (вершину на расстоянии `diam/2` от конца).
4. Проверяем, что все отмеченные на расстоянии `diam/2` от `p`.
   Если да — `p` ответ, иначе `NO`.

Ветвление «вбок» не помогает: если `x` на расстоянии `e` от `p` в боковом
поддереве, то расстояние до отмеченной `w` равно `e + dist(p, w)`, и для
равенства нужно `dist(p, w) = diam/2` для всех — а это уже проверено.

Сложность `O(n)`. Ловушка: проверять расстояния только до двух концов
диаметра.

## G. Dijkstra? (20C)

Обычная Дейкстра от 1, расстояния `long long`, в куче пары
`(dist, v)`. При релаксации запоминаем `parent[v] = u`.

Восстанавливаем путь от `n` к `1` по `parent`, разворачиваем, печатаем.
Если `dist[n]` бесконечно — `-1`.

Сложность `O((n + m) log n)`. Ловушки: `int` для расстояний (до `10^18`),
и `parent`, перезаписываемый при равных расстояниях без причины (это
не ошибка, но легко получить цикл, если обновлять `parent` у уже
обработанной вершины).

## H. The Shortest Statement (1051F)

`m − n ≤ 20` — значит, взяв любое остовное дерево, мы оставим не более
21 ребра вне его. Концы этих рёбер — не более 42 «особых» вершин.

Кратчайший путь `u → v` либо целиком лежит в дереве (и тогда его длина —
это `dist_tree(u, v)` через `LCA` и префиксные расстояния), либо проходит
через одну из особых вершин `s` (потому что любое «недревесное» ребро
инцидентно особой вершине).

Поэтому: строим остов, считаем `LCA` и глубины, запускаем Дейкстру
от каждой особой вершины (`≤ 42` запуска, каждый `O(m log n)`), и на запрос

```
answer = min( dist_tree(u,v),  min_s ( d_s[u] + d_s[v] ) )
```

Сложность `O(42·m log n + q log n)`. Ловушка: пытаться отвечать запросами
по всему графу (это `O(q·m log n)`) и не заметить, что «лишних» рёбер
всего 20.
