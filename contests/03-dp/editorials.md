# 03. ДП — разборы

## A. An oscillating subsequence (106189D)

Нужна самая длинная подпоследовательность, где каждый внутренний элемент —
локальный экстремум (строго больше или строго меньше обоих соседей).

Удобно думать про смены направления: подпоследовательность максимальна, если
брать первый элемент и затем каждый раз, когда направление меняется, брать
точку разворота. Формально: выпишем индексы, где знак `a[i+1] - a[i]`
меняется (нули — равные соседи — пропускаем), и добавим границы.

Почему это оптимум: любой колебательный ответ обязан содержать по элементу
из каждого «зубца» монотонного участка, а локальные экстремумы дают ровно
по одному и достижимы.

Если монотонных смен нет (весь массив неубывающий или невозрастающий) —
печатаем `0`: колебательной подпоследовательности длины ≥ 3 не существует.

Сложность `O(n)`. Ловушка: брать все элементы подряд (тогда соседи не
экстремумы) и забыть требование «длина хотя бы 3».

## B. Tree Painting (104015I)

Условие «ровно одно ребро соединяет разные цвета» означает: множество
чёрных вершин и множество белых связаны, и между ними проходит ровно одно
ребро. Значит, это ребро разрезает дерево на две части, каждая из которых
одноцветна. Цветов поровну, то есть части должны быть размера `n/2`.

Отсюда алгоритм: подвесим дерево за 1, посчитаем размеры поддеревьев.
Если найдётся ребро, у которого размер поддерева ровно `n/2`, — красим это
поддерево в 0, остальное в 1. Если такого ребра нет, ответа не существует
(других способов получить одноцветные части нет).

Сложность `O(n)`. Ловушка: пытаться красить жадно от листьев — для дерева
с нечётными поддеревьями это заходит в тупик, хотя ответ есть.

## C. Chain Reaction (607A)

Маяки активируются справа налево, новый маяк ставится правее всех, значит
он уничтожает некоторый суффикс массива, а уцелеть может только префикс.

Отсортируем маяки по позиции. `dp[i]` — сколько маяков уцелеет среди
`1..i`, если маяк `i` уцелел. Тогда все маяки левее `a[i] - b[i]` тоже
уцелели (маяк `i` до них не достаёт), и

```
dp[i] = dp[j] + 1,   j = max{ t : a[t] < a[i] - b[i] }
```

`j` ищется бинпоиском или указателем, `dp[0] = 0`.
Ответ: `n - max(dp[i])`.

Сложность `O(n log n)`. Ловушка: считать, что уничтожаются все маяки
в радиусе, включая правые, — маяк бьёт только влево.

## D. Bicolorings (1051D) — crossover

Классическое ДП по профилю. Состояние: номер столбца, маска столбца
(2 бита, 4 варианта) и число компонент. `dp[c][mask][k]`.

Старт: первый столбец даёт `1` компоненту, если клетки одного цвета,
и `2`, если разные.

Переход от маски `pm` к маске `m`:

- если клетки в `m` одного цвета: они образуют одну компоненту. Она новая,
  только если слева нет клетки того же цвета (`m` не совпадает с `pm`
  ни в одной позиции). Иначе компонента уже существует;
- если клетки разные: каждая клетка — отдельная компонента, и она новая,
  если её цвет отличается от левой соседки в своей строке.

То есть `delta` считается по двум сравнениям с `pm` и одному сравнению
внутри столбца; `dp[c+1][m][k+delta] += dp[c][pm][k]`.

Ответ: `dp[n][*][k]`, всё по модулю `998244353`.
Сложность `O(n·k·16)`. Ловушка: забыть, что две одинаковые клетки нового
столбца склеиваются в одну компоненту, и посчитать `+2`.

## E. Distance in Tree (161D)

Считаем пары в их LCA. `dp[v][d]` — количество вершин в поддереве `v`
на расстоянии `d` от `v` (включая `dp[v][0] = 1`).

Обрабатывая ребёнка `u` вершины `v`: сначала добавляем к ответу пары,
проходящие через `v`, — для каждого `d` берём `dp[v][d] · dp[u][k-1-d]`;
только после этого вливаем `dp[u]` в `dp[v]` со сдвигом на 1.

Ответ — сумма по всем `v`. Сложность `O(n·k)`: при `n = 5·10^4` и `k = 500`
это `2.5·10^7`, но константа маленькая, и глубина `dp` не превышает размера
поддерева — на практике ещё меньше.

Ловушка: влить ребёнка в `dp[v]` до подсчёта пар — тогда пары внутри
одного поддерева посчитаются дважды.

## F. RBS (104015L)

Бросается в глаза `n ≤ 20` — это ДП по подмножествам. Ключевое наблюдение:
баланс конкатенации зависит только от набора строк, а не от их порядка,
поэтому состояние — маска, а баланс восстанавливается как сумма балансов.

`dp[mask]` — максимум RBS-префиксов, которых можно добиться, выписав строки
из `mask` в каком-то порядке, при условии, что баланс ни разу не был
отрицательным. Если такого порядка нет, `dp[mask] = -∞`.

Переход: добавляем строку `s` к состоянию `mask` с балансом `b`.

- Если минимальный префикс `s` меньше `-b`, порядок недопустим (баланс
  уйдёт в минус, и после этого RBS-префиксов уже не будет никогда).
- Иначе прирост — число позиций внутри `s`, где накопленный баланс равен
  `-b` (именно там вся конкатенация обнуляется).

Прирост для каждой пары `(s, b)` считается один раз: для строки храним
карту «значение префикса → сколько раз встречается» и минимум префикса.

Ответ: `dp[2^n - 1]`. Сложность `O(2^n · n)`, память `O(2^n)`.
Ловушка: считать прирост по «числу нулей баланса внутри строки» без учёта
стартового баланса `b`.

## G. Tree problem (106035G)

Для каждой вершины нужен самый частый цвет в её поддереве (при равенстве —
меньший цвет). Это учебная задача на «DSU на дереве» / слияние меньшего
в большее.

Идём снизу вверх. Для вершины держим `map<color, count>` по её поддереву
и текущий максимум `(count, color)`. Начиная с самой большой карты среди
детей (или пустой), вливаем остальные карты: при каждом добавлении
обновляем счётчик цвета и максимум.

Сложность: каждый элемент переезжает `O(log n)` раз, суммарно `O(n log n)`
(плюс логарифм на `map`). Ловушка: сливать все карты в карту текущей вершины
без выбора самой большой — тогда на «бамбуке» получится `O(n^2)`.

## H. Roman and Numbers (401D)

Длина числа ≤ 18, значит перестановки — это маски: `dp[mask][rem]` —
сколько способов расставить цифры из `mask` в начало числа так, чтобы
остаток по модулю `m` был `rem`.

Переход: ставим цифру `d` из `mask` на следующую позицию,
`newrem = (rem·10 + d) mod m`. Первая цифра не может быть нулём.

Одинаковые цифры дают одинаковые числа, а маски их различают, поэтому
в конце делим ответ на `∏ cnt[d]!` (перестановки одинаковых цифр).

Сложность `O(2^len · len · m)`: при `len = 18`, `m ≤ 100` это около `5·10^7` —
на грани, поэтому маску удобно хранить по цифрам с пропуском повторов
(«next different digit»), тогда множитель меньше.

Ловушка: не поделить на факториалы кратностей и получить завышенный ответ;
и не отсечь ведущий ноль.
