# 03. ДП — разборы

## A. An oscillating subsequence (106189D)

Нужна самая длинная подпоследовательность, где каждый внутренний элемент —
строгий локальный экстремум.

Максимум достигается на «первый элемент + все точки разворота»: выпишем
индексы, где меняется знак `a[i+1] − a[i]` (нули — равные соседи —
пропускаем), и добавим границы. Любой колебательный ответ обязан содержать
по элементу из каждого монотонного участка, а локальные экстремумы дают
ровно по одному.

Если смен направления нет (массив монотонный) — печатаем `0`.

Сложность `O(n)`. Ловушка: брать все элементы подряд (тогда соседи —
не экстремумы) и забыть требование «длина ≥ 3».

## B. Tree Painting (104015I)

«Ровно одно ребро между разными цветами» означает: это ребро разрезает
дерево на две одноцветные части. Цветов поровну → части размера `n/2`.

Подвешиваем за 1, считаем размеры поддеревьев. Если есть ребро, у которого
размер поддерева ровно `n/2`, — красим это поддерево в 0, остальное в 1.
Иначе ответа нет.

Сложность `O(n)`. Ловушка: красить жадно от листьев — на дереве с нечётными
поддеревьями это заходит в тупик, хотя ответ есть.

## C. Chain Reaction (607A)

Маяки активируются справа налево, новый ставится правее всех, значит он
уничтожает суффикс, а уцелеть может только префикс.

Сортируем по позиции. `dp[i]` — сколько уцелеет среди `1..i`, если `i`
уцелел. Тогда все маяки левее `a[i] − b[i]` тоже уцелели:

```
dp[i] = dp[j] + 1,   j = max{ t : a[t] < a[i] − b[i] }
```

Ответ `n − max dp[i]`. Сложность `O(n log n)`. Ловушка: считать, что маяк
бьёт и вправо, — он бьёт только влево.

## D. Bicolorings (1051D)

ДП по профилю: `dp[c][mask][k]` — номер столбца, маска столбца (2 бита),
число компонент.

Первый столбец: `1` компонента, если клетки одного цвета, иначе `2`.

Переход от маски `pm` к `m`:

- клетки `m` одного цвета — одна компонента; она новая, только если слева
  нет клетки того же цвета (иначе компонента уже есть);
- клетки разные — каждая даёт компоненту, если её цвет отличается
  от левой соседки в своей строке.

Ответ `dp[n][*][k]` по модулю `998244353`. Сложность `O(n·k·16)`.
Ловушка: посчитать `+2` для одинаковых клеток нового столбца.

## E. Magic Numbers (628D)

Цифровая ДП. Считаем `f(x)` — сколько «d-магических» чисел не больше `x`,
ответ `f(b) − f(a−1)`.

Важно: `a` и `b` одной длины, значит все числа отрезка имеют эту длину `L`,
и `f` достаточно считать только для `L`-значных чисел (первая цифра не ноль).

Состояние: `(pos, rem, tight)`, где `pos` — позиция слева (0-based),
`rem` — остаток по модулю `m`, `tight` — совпадает ли префикс с `x`.

Переход: перебираем цифру `c` от 0 до `9` (на первой позиции от 1).
Пусть `p = pos + 1` (позиция с единицы):

- `p` чётная → `c` обязана быть равна `d`;
- `p` нечётная → `c ≠ d`.

Новый остаток `(rem·10 + c) mod m`. Ответ — сумма по `rem = 0`.

Сложность `O(L·m·10)`: при `L, m ≤ 2000` это около `4·10^7`.
Ловушки: перепутать чётность (считать с нуля, а не с единицы), забыть
запрет ведущего нуля и не вычесть единицу из `a` как из строки.

## F. Distance in Tree (161D)

Считаем пары в их LCA. `dp[v][d]` — число вершин в поддереве `v`
на расстоянии `d` от `v` (включая `dp[v][0] = 1`).

Обрабатывая ребёнка `u` вершины `v`: сначала добавляем пары, проходящие
через `v`, — для каждого `d` берём `dp[v][d] · dp[u][k−1−d]`; только потом
вливаем `dp[u]` в `dp[v]` со сдвигом на 1.

Сложность `O(n·k)`; фактически меньше, потому что глубина `dp` ограничена
размером поддерева. Ловушка: влить ребёнка до подсчёта пар — пары внутри
одного поддерева посчитаются дважды.

## G. RBS (104015L)

`n ≤ 20` — ДП по подмножествам. Ключ: баланс конкатенации зависит только
от набора строк, а не от порядка, поэтому состояние — маска, баланс
восстанавливается как сумма балансов.

`dp[mask]` — максимум RBS-префиксов при каком-то порядке строк из `mask`,
если баланс ни разу не был отрицательным; иначе `−∞`.

Переход: добавляем строку `s` к состоянию с балансом `b`.

- Если минимальный префикс `s` меньше `−b` — порядок недопустим.
- Иначе прирост — число позиций внутри `s`, где накопленный баланс равен
  `−b` (там вся конкатенация обнуляется).

Для каждой строки заранее храним карту «значение префикса → сколько раз»
и минимум префикса. Ответ `dp[2^n − 1]`, сложность `O(2^n·n)`.

Ловушка: считать прирост без учёта стартового баланса `b`.

## H. Tree problem (106035G)

Для каждой вершины нужен самый частый цвет в поддереве (при равенстве —
меньший). Это СНМ на дереве / слияние меньшего в большее.

**Как сливать.** Идём снизу вверх (обход в глубину, обработка после детей).
Для вершины `v` держим `map<color, count>` по её поддереву и текущий ответ —
пару `(count, color)`, где при равных `count` выигрывает меньший `color`.

1. Выбираем самого «тяжёлого» ребёнка (у кого карта больше) и стартуем
   с его карты, добавив цвет самой `v`.
2. Для каждого остального ребёнка перебираем его карту и вливаем:
   `cnt[color] += add`, обновляя текущий максимум по правилу «больше count
   или равный count и меньший цвет».
3. Ответ `v` — текущий максимум.

**Почему быстро.** Каждый элемент при слиянии переезжает в карту, размер
которой хотя бы удвоился, поэтому переездов на элемент `O(log n)`,
итого `O(n log n)` операций с `map`, то есть `O(n log² n)` по времени
и `O(n)` памяти.

Ловушка: сливать всё в карту текущей вершины без выбора самой большой —
на «бамбуке» получится `O(n²)`.

## I. Roman and Numbers (401D)

Перестановки цифр — маски: `dp[mask][rem]` — сколько способов расставить
цифры из `mask` в начало числа так, чтобы остаток был `rem`.

Переход: ставим цифру `c` из `mask` на следующую позицию,
`newrem = (rem·10 + c) mod m`. Первая цифра не ноль.

Одинаковые цифры дают одинаковые числа, а маски их различают, поэтому
в конце делим на `∏ cnt[c]!`.

Сложность `O(2^len · len · m)` — на грани при `len = 18`, `m = 100`;
помогает пропуск повторяющихся цифр при переборе переходов.

Ловушки: не поделить на факториалы кратностей и не отсечь ведущий ноль.
