# 04. Деревья отрезков — разборы

## A. Time to reap the harvest (104452B)

Нужно `Σ max(a_i − L, 0)`. Отсортируем высоты один раз и посчитаем
суффиксные суммы. На запрос `L`:

```
idx = upper_bound(a, L)
ans = suffix[idx] − L · (n − idx)
```

Сложность `O(n log n + q log n)`. Ловушка: считать в `int` — сумма до `10^14`.

## B. Memory Manager (106189M)

Держим `set` свободных страниц. Для запроса `h`:

```
it = free.lower_bound(h)
кандидаты: it (первая свободная ≥ h) и prev(it) (последняя < h)
```

Выбираем ближайшую по `|r − h|`, при равенстве — меньший номер, удаляем
из `set`. Если `it` или `prev(it)` не существует — берём только имеющегося.

Сложность `O(k log n)`. Ловушка: искать свободную, шагая вправо/влево
по одному — на длинных занятых блоках это `O(n)` на запрос.

## C. Just another array problem (104454N)

Массив всегда остаётся циклическим сдвигом исходного отсортированного,
поэтому достаточно хранить сдвиг `shift` (сколько позиций «ушедло» вправо).

Для запроса `x`: `L = lower_bound(a, x)`, `R = upper_bound(a, x) − 1`.
Если `L > R` — числа нет, ответ `-1`. Иначе переводим позиции в текущие:

```
cur(p) = (p − shift + n) mod n
```

Если `cur(L) ≤ cur(R)`, блок не разрезан — ответ `cur(L) + 1`.
Если `cur(L) > cur(R)`, блок «разрезан» концом массива: он занимает
конец и начало, значит первое вхождение в текущем порядке — позиция `1`.

Сложность `O(log n)` на запрос. Ловушка: искать `x` бинпоиском по
«повёрнутому» массиву и путаться в сравнениях — при известном сдвиге
это не нужно.

## D. High Load Database (104874H)

Для фиксированного `t` — жадно: набираем подряд идущие транзакции, пока
сумма не превысит `t`. Переход от `i` к следующей позиции — бинпоиск по
префиксным суммам: `j = upper_bound(pref, pref[i] + t) − 1`, счётчик +1,
`i = j`. Если какая-то `a_i > t`, ответ «Impossible».

Прямое суммирование по всем запросам — `O(nq)`. Но если `t` повторяется,
ответ считаем один раз (мемоизация по `t`), а стоимость одного нового `t` —
`O((sum/t) · log n)`, где `sum` — общая сумма. Суммарно по всем различным
`t`:

```
Σ_t sum/t · log n = sum · H(sum) · log n
```

при `sum ≤ 10^6` это около `1.4·10^7` операций — проходит.

Ловушка: не заметить, что `t` может быть больше суммы (тогда один батч),
и не обработать `a_i > t`.

## E. Financial Discipline (104777K)

Деньги обновляются как `m = max(0, m + a_i − X)`. Раскручиваем рекурсию:

```
m_n = max(0, b_n, b_n + b_{n−1}, ..., b_n + ... + b_1),  b_i = a_i − X
```

то есть ответ — максимум сумм суффиксов. Через префиксные суммы `S`:

```
answer(X) = max_{0 ≤ j ≤ n} [ (S_n − S_j) − X·(n − j) ]
           = max_j [ c_j + m_j·X ],
c_j = S_n − S_j,   m_j = −(n − j)
```

Это максимум `n + 1` линейной функции от `X`. Строим верхнюю огибающую
(выпуклая оболочка прямых, CHT): наклоны `m_j` возрастают, поэтому
оболочка строится за `O(n)`, а запрос — бинарным поиском по точкам
пересечения.

Можно и проще: отсортировать запросы по `X` и идти по оболочке указателем —
`O(n log n + q log q)`.

Ловушка: забыть `j = n` (нулевой суффикс) — тогда ответ может стать
отрицательным, а должен быть `0`.

## F. Mex and Cards (104012M)

Обозначим `c_v` — количество карт значения `v`.

**Формула.** Куча имеет мекс больше `k` тогда и только тогда, когда в ней
есть карты всех значений `0..k`. Значит куч с мексом > `k` не больше
`pref[k] = min(c_0, ..., c_k)`, и это достижимо: разложим карты по
«слоям» — в `i`-ю кучу по одной карте каждого значения, пока хватает.
Сумма мексов равна числу пар (куча, `k`) с мексом > `k`:

```
answer = Σ_{k=0}^{n−1} pref[k]
```

Пример: `c = (2, 2, 1)` (две нуля, две единицы, одна двойка) даёт
`pref = (2, 2, 1)` и ответ `5`. Это достижимо: кучи `{0,1,2}` (мекс 3),
`{0,1}` (мекс 2), `{2}` (мекс 0) — сумма `5`. Если считать «в лоб» по
слоям, легко получить 4 и потерять одну единицу мекса.

**Обновления.** Меняется одна `c_v` на ±1. Массив `pref` не возрастает;
при изменении `c_v` меняется только участок `k ≥ v`. Новое значение
в начале участка:

```
x = min(pref[v−1], c_v)     (pref[−1] = +∞)
```

Далее `pref[k] = x`, пока не встретится `c_p < x`; начиная с `p` массив
остаётся прежним (там минимум определяют те же `c`). Значит одно
обновление — это `assign` на отрезке `[v, p)` и пересчёт суммы.

Две структуры: дерево по `c` с «найти первую позицию правее `v` со
значением `< x`» и дерево по `pref` с `assign` и суммой. Обе операции —
`O(log n)`.

Ловушка: пересчитывать `pref` от `v` до конца каждый раз — это `O(n)` и TLE.

## G. Army Creation (813E) — персистентное ДО

Запрос: в отрезке `[l, r]` каждое значение разрешено не больше `k` раз,
сколько элементов можно взять.

Для каждой позиции `i` найдём `p_i` — позицию `k`-го предыдущего вхождения
того же значения (если таких меньше `k`, то `p_i = 0`). Тогда элемент `i`
можно взять, только если `p_i < l` (иначе слева уже есть `k` таких же).
Ответ — количество `i ∈ [l, r]` с `p_i < l`.

Это стандартный запрос «сколько чисел меньше `l` на отрезке позиций».
Строим персистентное дерево отрезков по позициям: версия `i` — это версия
`i−1` плюс единица в точке `p_i`. Тогда ответ — разность запросов
«количество в `[0, l−1]`» между версиями `r` и `l−1`.

Сложность `O((n + q) log n)`, память `O(n log n)`.
Ловушка: считать `p_i` «предыдущее вхождение» вместо `k`-го предыдущего.

## H. Points (19D) — 2D

Операции: добавить точку; удалить точку; запрос — среди точек с `x > X`
и `y > Y` найти минимальную по `x`, при равенстве минимальную по `y`.

Сжимаем все `x`, которые встретятся в добавлениях. Дерево отрезков по `x`:
в узле храним максимум `y` среди точек этого диапазона. Поиск ответа:

1. Находим самый левый лист с `x > X`, у которого максимум `y` в узле
   больше `Y` — обычный спуск по дереву за `O(log n)`.
2. В этом `x` нужна минимальная `y > Y` — для каждого `x` держим `set`
   его `y` и берём `upper_bound(Y)`.

Ответ — эта точка. Добавление/удаление — обновление `set` и точки в дереве,
`O(log n)`.

Сложность `O((n + q) log n)`. Ловушка: спуск «в первый узел с максимумом
больше `Y`» должен идти влево, только если левый сын подходит, иначе вправо;
и `set` для каждого `x` нужен отдельный, иначе теряется минимальная `y`.
