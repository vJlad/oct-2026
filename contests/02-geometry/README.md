# 02. Геометрия — вычислительная

Только вычислительная геометрия: формулы, площади, касания, пересечения,
сканлайн, оболочка. Никаких конструктивов и «геометрия + структуры».

Формат: 3 часа, индивидуально, 8 задач, ICPC-скоринг.
Условия на английском, разборы на русском.

## Про оболочку

F (166B) — про выпуклость и бинарный поиск по оболочке: дан строго выпуклый
многоугольник, нужно проверить, что второй многоугольник лежит строго внутри.
Наивно — `O(n·m)`, правильно — `O(m log n)`: бинпоиск сектора от нулевой
вершины, потом одна проверка ребра.

Задачи «постройте выпуклую оболочку и найдите диаметр множества» в доступном
ICPC-пуле нет — я отдельно прогрепал ~570 условий из 107 гимнов NERC
по словам `convex hull`, `hull`, `выпукл`, `оболочк`. Если нужна именно
постройка, есть два варианта из архива: [277B Set of Points](https://codeforces.com/problemset/problem/277/B)
(построить множество точек с ровно `m` вершинами оболочки) и
[70D Professor's Task](https://codeforces.com/problemset/problem/70/D)
(динамическая оболочка: добавление точек и проверка «внутри»). Скажете —
поставлю любую из них вместо F.

Идея «оболочка + два указателя = диаметр» разобрана в разделе
«Что обсудить»: на самом контесте её негде применить, но она напрямую
продолжает F.

## Баланс

- A–B — 20–40 минут.
- C–E — ядро: линза, сканлайн, пересечение прямоугольников.
- F–H — на дорешивание. F — первый «оболочечный» алгоритм, G — бинпоиск
  по геометрическому предикату, H — разбор конфигураций.

## Что обсудить после

1. B — почему гарантия на расстояния убивает тройные пересечения.
2. D — почему «пересечение k отрезков» считается по покрытию, и почему
   события `r+1`, а не `r`.
3. F → диаметр. Постройте оболочку за `O(n log n)`, затем двумя указателями
   (rotating calipers) найдите самую далёкую пару за `O(h)`. Это ровно то,
   о чём вы спрашивали, и хорошее продолжение после контеста.
4. H — почему радиус не монотонен и приходится разбирать конфигурации.
