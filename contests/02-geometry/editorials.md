# 02. Геометрия — разборы

## A. Bounding Boxes (106193B)

Коробку можно поворачивать, но стороны остаются параллельны сторонам
упаковки. Значит коробка с измерениями `(a,b,c)` помещается в упаковку
`(w,h,d)` тогда и только тогда, когда отсортированные по возрастанию
тройки сравнимы покоординатно.

Отсортируем измерения каждой упаковки. Сувенирная коробка должна влезать
во все упаковки, поэтому её отсортированные измерения — поэлементные
минимумы: `min_w · min_h · min_d`. Больше объёма не получить: любое
измерение упирается в одну из упаковок.

Сложность `O(n)`. Ловушка: брать минимум по каждой позиции без сортировки —
тогда `(2,10,10)` и `(3,8,4)` дают неправильный ответ.

## B. Rectangle Restoration (104015D)

Стороны прямоугольника — `a, a, b, b`. Сумма двух сторон принимает одно
из значений `2a`, `a+b`, `2b`; сумма трёх — `2a+b` или `a+2b`.
Разных итоговых случаев три (остальные симметричны):

| Случай | `a`, `b` | Периметр | Условие |
|---|---|---|---|
| `x=2a`, `y=2a+b` | `x/2`, `y-x` | `2y-x` | `y > x` |
| `x=2a`, `y=a+2b` | `x/2`, `(y-x/2)/2` | `x/2 + y` | `y > x/2` |
| `x=a+b`, `y=2a+b` | `y-x`, `2x-y` | `2x` | `x < y < 2x` |

Берём минимум по допустимым случаям (все условия строгие, стороны
положительны), печатаем с точностью `1e-4`. Если ни один не подошёл — `-1`.

Сложность `O(1)`. Ловушка: считать, что `x` и `y` — обязательно «две разные»
и «три разные» стороны; на самом деле важны только значения сумм.

## C. Points and Minimum Distance (104777I)

Нижняя оценка: путь, обходящий точки, обязан «покрыть» размах по `x`
и размах по `y`, поэтому его длина не меньше
`(max x - min x) + (max y - min y)`.

Все `2n` чисел раздаются в `x` и `y`. Чтобы минимизировать сумму размахов,
разобьём отсортированный массив на две половины: первые `n` чисел — `x`,
последние `n` — `y`. Оценка становится
`(a[n-1]-a[0]) + (a[2n-1]-a[n])`, и она достижима: точки `(a[i], a[n+i])`,
выписанные по возрастанию `i`, дают путь, где обе координаты монотонно
растут, значит его длина в точности равна сумме размахов.

Сложность `O(n log n)`. Ловушка: вывести точки в произвольном порядке —
путь станет длиннее оценки (проверяется именно порядок обхода).

## D. Alley (104805E)

Все центры на одной прямой, расстояние между любыми двумя кругами не меньше
большего радиуса. Отсортируем по `x`.

**Лемма.** Несоседние круги не пересекаются. Действительно, для `i < j < k`
выполнено `|x_j - x_i| ≥ max(r_i, r_j) ≥ r_i` и `|x_k - x_j| ≥ max(r_j, r_k) ≥ r_k`,
значит `|x_k - x_i| ≥ r_i + r_k`.

Следствие: пересекаться могут только соседние круги, и тройных пересечений
нет. Значит

```
S = Σ π·r_i² − Σ площадь_линзы(i, i+1)
```

где сумма берётся по тем соседним парам, у которых `|x_i - x_{i+1}| < r_i + r_{i+1}`.

Площадь линзы двух кругов радиусов `a`, `b` на расстоянии `d`:

```
cos α = (d² + a² − b²) / (2da),   cos β = (d² + b² − a²) / (2db)
S = a²·α + b²·β − ½·sqrt((−d+a+b)(d+a−b)(d−a+b)(d+a+b))
```

Сложность `O(n log n)`. Точность: `long double`, `π = acos(-1.0L)`,
печатать 8+ знаков. Ловушка: складывать линзы для всех пар или забыть,
что при касании (`d = a + b`) площадь линзы нулевая.

## E. Ideal Pyramid (104874I)

Пирамида с уклоном 45° и центром `(xc, yc)` в точке `(x, y)` имеет высоту
`h - max(|x - xc|, |y - yc|)`. Условие «обелиск внутри»:

```
max(|x_i - xc|, |y_i - yc|) ≤ h - h_i
```

то есть `xc ∈ [x_i - (h-h_i), x_i + (h-h_i)]` и аналогично по `y`.
Для фиксированного `h` проверка — непустое пересечение отрезков по `x`
и по `y`.

Условие монотонно по `h`, поэтому бинпоиск от `max h_i` до `4·10^8`
(больше не нужно: размах координат `2·10^8`). Центр — любая точка
пересечения, например левые концы отрезков.

Сложность `O(n log C)`. Ловушка: считать, что высота убывает как евклидово
расстояние, — тогда условие станет `sqrt(dx²+dy²) ≤ h-h_i` и ответ будет
другим.

## F. Area of Two Circles' Intersection (600D) — crossover

`d` — расстояние между центрами, `r1 ≥ r2` после возможного обмена.

1. `d ≥ r1 + r2` — окружности не пересекаются, ответ `0`.
2. `d ≤ r1 − r2` — меньший круг целиком внутри, ответ `π·r2²`.
3. Иначе — линза. Площадь считается как сумма двух «шапочек»:
   сектор большого круга минус треугольник плюс то же для малого:

```
α = acos((d² + r1² − r2²) / (2·d·r1))
β = acos((d² + r2² − r1²) / (2·d·r2))
S = r1²·α + r2²·β − ½·sqrt((−d+r1+r2)(d+r1−r2)(d−r1+r2)(d+r1+r2))
```

Сложность `O(1)`. Точность: координаты до `1e9`, поэтому `d²` до `4·10^18`
считается в `long double`, а не в `double`. Ловушка: проверить случай
«один внутри другого» до общей формулы (иначе `acos` получит аргумент
вне `[−1, 1]` и выдаст `nan`).

## G. Polygons (166B) — crossover

`A` строго выпуклый и обходится по часовой стрелке, значит точка `P`
внутри, если она лежит строго справа от каждого ребра:
`cross(A[i+1]-A[i], P-A[i]) < 0`.

Проверять все `n` рёбер на каждую из `m` вершин — `2·10^9` операций,
не проходит. Используем выпуклость: из вершины `A[0]` проводим веер
диагоналей. Бинпоиском по углу находим сектор `[A[0], A[i], A[i+1]]`,
в котором лежит `P`, затем проверяем одно ребро `A[i] → A[i+1]`
и две крайние диагонали. Все неравенства строгие: точка на границе
или на продолжении ребра даёт `NO`.

Сложность `O(m log n)`. Ловушка: не обработать точки вне угла между
`A[1]` и `A[n-1]`; и перепутать знак из-за направления обхода.

## H. 1%-Euclidean (104848I) — crossover

Точный ответ — сумма `n(n-1)/2` корней, при `n = 5·10^5` это `1.25·10^11`
слагаемых. Но требуется точность 1%, и этим надо воспользоваться.

Оценка Монте-Карло: выбираем `M` случайных пар точек (равномерно по всем
парам), считаем среднее расстояние `avg`, ответ `avg · n(n-1)/2`.
Стандартная ошибка среднего падает как `1/√M`: при `M = 10^6` относительная
ошибка порядка `10^{-3}` — с запасом внутри 1%.

Практика: фиксируйте seed, берите `M = min(n(n-1)/2, 10^6)`, для маленьких
`n` (например, `n ≤ 3000`) считайте точный двойной цикл.
Сложность `O(n + M)`.

Ловушка: искать «умный» точный алгоритм и застрять — задача идейно про
оценку, а не про геометрию. Вторая ловушка — брать пары неравномерно
(например, только соседние после сортировки): смещение не скомпенсируется.

# Бонус (вне контеста)

## Rectangles (102788B)

Количество внешних клеток прямоугольника `w×h`:
`wh - (w-2)(h-2) = 2w + 2h - 4`. Внутренних: `(w-2)(h-2)`.
Условие «внутренних в `n` раз больше»:

```
(w-2)(h-2) = n(2w + 2h - 4)
```

Обозначим `a = w-2`, `b = h-2`; тогда `2w+2h-4 = 2a+2b+4`, и

```
ab - 2na - 2nb = 4n   ⟺   (a - 2n)(b - 2n) = 4n(n+1)
```

Значит `a - 2n` — делитель `4n(n+1)`. Раскладываем `n` и `n+1` на простые
(пробное деление до `√n ≈ 31623`), генерируем делители `4n(n+1)`,
для каждого `d ≤ √(4n(n+1))` получаем `a = d + 2n`, `b = 4n(n+1)/d + 2n`
и стороны `(a+2, b+2)`. Сортируем по меньшей стороне.

Сложность `O(√n + τ·log τ)`. Ловушка: перебирать делители до `2n`
вместо `√(4n(n+1))` — при `n = 10^9` это TLE.
