# 09. Эпилог — разборы

## A. Phoenix and Beauty (1348B)

Условие «все подмассивы длины `k` имеют одинаковую сумму» равносильно
периодичности с периодом `k`: `b_i = b_{i+k}`. Действительно, разность
соседних окон равна `b_{i+k} − b_i`, и она должна быть нулём.

Значит достаточно построить блок длины `k` и повторять его.

**Когда невозможно.** Если различных чисел в `a` больше `k`, то любой блок
длины `k` содержит не больше `k` различных значений, и `a` не влезет.

**Построение.** Возьмём различные значения `a` в порядке первого появления,
дополним блок до длины `k` любыми числами (например, единицами) и выведем
блок `n` раз. Длина `n·k ≤ 10^4`.

Почему `a` — подпоследовательность: каждый блок содержит все различные
значения, поэтому, идя по `a` слева направо, очередной элемент всегда
находится в текущем или следующем блоке.

Сложность `O(n·k)`. Ловушка: отсортировать различные значения — тогда
порядок в `a` может не восстановиться.

## B. Jumping Through Segments (1907D)

Ответ монотонен по `k`, поэтому бинпоиск.

**Проверка для фиксированного `k`.** Пусть после `i−1` шагов игрок может
оказаться в любой точке отрезка `[L, R]` (изначально `[0, 0]`). Тогда после
`i`-го шага достижимо `[L−k, R+k]`, а попасть надо в `[l_i, r_i]`:

```
L' = max(l_i, L − k),   R' = min(r_i, R + k)
```

Если `L' > R'` — такой `k` не подходит.

Границы бинпоиска: `0 … 10^9`. Сложность `O(n log C)` на тест.
Ловушка: проверять только «можно ли дотянуться до правого конца», не
отслеживая левый.

## C. Good Sequences (264B)

`dp[v]` — длина лучшей цепочки, заканчивающейся ровно числом `v`.
Числа идут по возрастанию, поэтому обрабатываем их слева направо.

Ключ: следующее число может быть любым кратным любому простому делителю
текущего. Значит достаточно хранить `best[p]` — лучшую длину цепочки среди
уже обработанных чисел, делящихся на простое `p`.

Для очередного `a_i`:

```
dp = 1 + max{ best[p] : p — простой делитель a_i }
best[p] = max(best[p], dp)   для всех простых p | a_i
```

Ответ — максимум `dp`. Решето наименьших простых делителей до `10^5` даёт
факторизацию за `O(log a_i)`.

Сложность `O(A log A + n log A)`. Ловушка: искать переход перебором всех
предыдущих чисел — `O(n²)`.

## D. Yet Another Counting Problem (1342C)

Выражение `((x mod a) mod b) ≠ ((x mod b) mod a)` зависит только от остатков
`x` по `a` и `b`, а пара остатков повторяется с периодом `L = lcm(a, b)`:
`(x + L) mod a = x mod a` и аналогично по `b`.

Значит:

1. считаем для `x = 0 … L−1` признак «плохое» и префиксные суммы;
2. `f(x)` — число плохих в `[1, x]`:
   `f(x) = (x / L)·cnt + pref[x mod L]` (аккуратно с `x = 0`);
3. ответ на `[l, r]` — `f(r) − f(l−1)`.

`L ≤ 200·200 = 40000`, запросов до `500` на тест — всё быстро.

Сложность `O(L + q)`. Ловушка: считать честно до `10^18` (невозможно)
и путать индексацию префиксов при `x`, кратном `L`.

## E. Asya And Kittens (1131F)

Каждое событие «котята `x` и `y` в соседних клетках, перегородку убрали»
означает: клетка с `x` и клетка с `y` слились, значит их последовательности
стали соседними.

Мы вправе выбрать исходную расстановку, поэтому ориентацию слияния выбираем
сами: приклеиваем список компоненты `y` в конец списка компоненты `x`.
Списки храним двусвязными (или `std::list` с `splice`), чтобы склейка была
за `O(1)`.

В конце остаётся один список — это и есть ответ.

Сложность `O(n α(n))`. Ловушка: каждый раз переписывать списки целиком
(`O(n²)`) и забыть, что порядок слияний задан именно во входе.

## F. Edge Deletion (1076D)

Хорошая вершина — та, до которой остался путь длины `d_i`. Значит оставлять
имеет смысл только «тугие» рёбра: `d[u] + w = d[v]` или `d[v] + w = d[u]`.

Оставляем дерево: обходом от 1 по тугим рёбрам подключаем каждую вершину
одним ребром. Тогда `e` рёбер дают `e + 1` хорошую вершину, и это максимум:
граф с `e` рёбрами имеет не больше `e + 1` вершин в компоненте единицы.

Берём `e = min(k, n−1)` и выводим индексы первых `e` рёбер обхода.

Сложность `O(m log n)` (Дейкстра). Ловушка: оставлять произвольные рёбра
вместо тугих — тогда расстояния ломаются.

## G. Valuable Paper (1423B)

Нужно выбрать по одному ребру на каждый завод и аэропорт — это совершенное
паросочетание в двудольном графе. Стоимость решения — максимальный `d`
среди выбранных рёбер, и она монотонна: если при `D` паросочетание есть,
то при большем `D` тоже.

Бинпоиск по `D` (по отсортированным различным `d`), проверка — существует
ли совершенное паросочетание в графе из рёбер с `d ≤ D`.

При `N ≤ 10^4`, `M ≤ 10^5` нужен Hopcroft–Karp: `O(E√V)` на проверку,
`O(log M)` проверок. Кун с `O(VE)` на таких числах не проходит.

Сложность: `O(E√V · log M)` по времени, память `O(N + M)`.

Если даже при всех рёбрах паросочетания нет — `-1`.

Ловушка: проверять только «дотягиваемся ли до всех», а не именно
совершенное паросочетание (заводы и аэропорты по отдельности).

## H. Peter and Snow Blower (613A)

Многоугольник вращается вокруг точки `P` снаружи. Заметаемая область —
кольцо между окружностью, проходящей через самую далёкую точку, и
окружностью, касающейся ближайшей точки многоугольника:

```
S = π·(R² − r²)
```

- `R` — максимум расстояния от `P` до вершин;
- `r` — минимум расстояния от `P` до сторон, то есть минимум по всем рёбрам
  расстояния «точка — отрезок» (не прямая: ближайшая точка может быть
  в вершине).

Сложность `O(n)`. Точность: `long double`, координаты до `10^6`, ответ
печатать с 10+ знаками. Ловушка: считать расстояние до прямых вместо
отрезков — тогда `r` занижается.

## I. Petr# (113B)

`|t| ≤ 2000`, поэтому подстрок порядка `4·10^6` — перебор по началу и концу
проходит.

Считаем два полиномиальных хэша (или один 64-битный с рандомизированной
базой): `H` для `t` и `R` для перевёрнутой.

Для каждой позиции `i`, где начинается `sbegin`:
для каждой позиции `j`, где заканчивается `send` и `j ≥ i + |sbegin| − 1`,
подстрока `t[i..j]` подходит; кладём её хэш в множество.

Ответ — размер множества. Сложность `O(n²)` (с хэшами — `O(1)` на подстроку).

Ловушки: путать «начинается с `sbegin`» и «равна `sbegin`»; и забыть, что
`sbegin` и `send` могут пересекаться или совпадать.

## J. Sereja and Brackets (380C)

Дерево отрезков, в узле три числа:

- `open` — сколько `(` осталось без пары,
- `close` — сколько `)` осталось без пары,
- `pairs` — сколько пар собрано.

Слияние левого `L` и правого `R`:

```
t = min(L.open, R.close)
pairs = L.pairs + R.pairs + t
open  = L.open + R.open − t
close = L.close + R.close − t
```

Ответ на запрос — `2·pairs` для объединения отрезков.

`n ≤ 10^6`, `m ≤ 10^5` — нужен итеративный дерево отрезков (рекурсия
съест память и время).

Сложность: `O(n)` на построение, `O(log n)` на запрос, память `O(n)`.

Ловушка: хранить только пары, без остатков — тогда слияние невозможно.

## K. 505 (1391D)

**Когда ответа нет.** Если `min(n, m) ≥ 4`, возьмём квадрат `4×4`. Он
разбивается на четыре `2×2`, у каждого нечётная сумма единиц, значит сумма
по всему квадрату чётна — противоречие с требованием «нечётная».

Иначе транспонируем матрицу так, чтобы строк было `n ≤ 3` (столбцов может
быть много). Тогда единственные квадраты чётной длины — это `2×2`, и условие
сводится к «в каждом `2×2` нечётное число единиц».

**ДП.** `dp[col][mask]` — минимум изменений в первых `col` столбцах, если
последний столбец имеет маску `mask` (`2^n ≤ 8` вариантов). Переход
`pm → m` допустим, если для каждой пары соседних строк сумма четырёх битов
нечётна; стоимость перехода — число битов, где `m` отличается от столбца
матрицы.

Ответ — минимум по последней маске. Сложность `O(m · 2^n · 4)`, память
`O(2^n)`.

Ловушка: забыть проверить `min(n, m) ≥ 4` и получить «ответ» на задаче,
где его не существует.

## L. Test (25E)

Нужна кратчайшая строка, содержащая `s1`, `s2`, `s3`.

Шаг 1: выбросить строки, которые уже содержатся в других (иначе они
бесполезны).

Шаг 2: перебрать 6 порядков склейки. Для двух соседних строк `cur` и `nxt`
максимальное перекрытие — наибольшее `L`, при котором суффикс `cur` длины
`L` равен префиксу `nxt` длины `L`. Это ищется префикс-функцией строки
`nxt + '#' + хвост cur`: берём последнее значение `π`, не превосходящее
`|nxt|`.

Ответ — минимум суммарной длины по всем порядкам.

Сложность `O(6 · (|s1| + |s2| + |s3|))`. Ловушки: не убрать вложенные
строки (тогда перекрытие считается неверно) и забыть про разделитель `#`.

## M. Professor's task (70D)

Динамическая выпуклая оболочка: добавление точки и проверка «внутри ли».

Держим две оболочки — верхнюю и нижнюю — в `set` по `x`. Инвариант: точки
в каждой оболочке идут слева направо и образуют выпуклую цепочку.

**Добавление.** Вставляем точку в обе оболочки. Затем, пока тройка
(предыдущая, текущая, следующая) нарушает выпуклость, удаляем среднюю
вершину. Такой цикл суммарно даёт `O(q log q)`: каждая точка удаляется
не больше одного раза.

**Запрос «внутри».** Для точки `p`:

1. в верхней оболочке находим ребро `(a, b)` с `a.x ≤ p.x ≤ b.x`
   (`lower_bound` по `x`), точка должна лежать не выше прямой `ab`;
2. в нижней — не ниже.

Обе проверки — через векторное произведение. Отдельно аккуратно
обработайте `p.x`, совпадающий с крайними вершинами: оболочка может иметь
вертикальное ребро, и тогда сравнение идёт сразу с ним, а не с соседним.

Сложность `O(log q)` амортизированно на операцию. Ловушка: проверять
«внутри» честным перебором всех рёбер — `O(q)` на запрос.
