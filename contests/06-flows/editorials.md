# 06. Потоки — разборы

## A. Treasure Island (1214D)

Сетка `n × m`, часть клеток уже занята (`#`). Нужно убрать минимум свободных
клеток, чтобы из `(1,1)` нельзя было дойти до `(n,m)`.

По теореме Менгера это минимум вершинного разреза, то есть максимум
вершинно-непересекающихся путей. Через клетку входа и клетку выхода проходит
не больше одного пути каждая, поэтому ответ всегда `0`, `1` или `2`.

Модель: раздвоение вершин. Каждая свободная клетка (кроме старта и финиша)
превращается в `in → out` с ёмкостью 1; старт и финиш — с ёмкостью `∞`.
Между соседними клетками — `out(u) → in(v)` с `∞`. Максимальный поток из
`out(s)` в `in(t)` и есть ответ (0 — уже разделено, 2 — нужно две клетки).

Поток не превышает 2, поэтому даже на `10^6` клеток хватает двух
дополняющих путей (или двух BFS, если не хочется писать Дinic).

Сложность `O(nm)` по памяти и почти `O(nm)` по времени. Ловушки: пытаться
найти «разрезающую» клетку одним BFS (при ответе 2 их нет по отдельности)
и забыть, что старт и финиш удалять нельзя.

## B. Soldier and Traveling (546E)

Солдат из города `i` либо остаётся, либо переходит в соседний город по
одной дороге. Нужно получить ровно `b_i` в каждом городе.

Сначала проверяем `Σ a_i = Σ b_i`, иначе сразу `NO`.

Сеть с ёмкостями на вершинах (раздвоение):

```
исток → i_out : a_i
i_out → i_in  : ∞        (остаться)
i_out → j_in  : ∞        (для каждой дороги i–j)
j_in → сток   : b_j
```

Ответ `YES`, если максимальный поток равен `Σ b_i` (тогда все солдаты
распределены так, как нужно).

Сложность `O(flow)` на графе из `2n + 2` вершин. Ловушки: не добавить
ребро «остаться»; и проверять только поток, забыв про равенство сумм.

## C. Flawed Flow (269C)

Даны неориентированные рёбра и для каждой вершины (кроме стока) требуемый
суммарный выходящий поток. Нужно сориентировать рёбра.

Поток считать не нужно. Идём от стока `n`: каждое ещё не сориентированное
ребро направляем «в сторону уже обработанной вершины» и прибавляем его
к счётчику выходящего потока второго конца. Когда у вершины счётчик
сравнялся с требуемым — кладём её в очередь.

Почему работает: каждое ребро должно нести поток к стоку, а суммарный выход
вершины задан; ориентация «к обработанной» — единственная возможная,
и согласованность сумм гарантирует, что счётчик не переполнится.

Сложность `O(n + m)`. Ловушка: запускать max-flow — он тут не нужен и
не влезет по времени на плотных тестах.

## D. Array and Operations (498C)

Дано `n` чисел и `m` пар `(i, j)` с нечётной суммой индексов. Операция:
выбрать пару и поделить оба числа на общий простой делитель.

Индексы разбиваются на чётные и нечётные — граф пар двудольный. Задача
распадается по простым: для каждого `p` строим сеть

```
исток → (нечётные i) : e_i
(нечётные i) → (чётные j) по парам : ∞
(чётные j) → сток : e_j
```

где `e_i` — степень `p` в числе. Максимальный поток для `p` — сколько
операций можно сделать с этим простым; ответ — сумма по всем `p`.

Сложность: `O(ω · flow)`, простых немного (факторизация до `31623`).
Ловушка: строить одну сеть на все простые — поток «смешает» делители.

## E. Delivery Bears (653D)

`b` медведей несут одинаковый груз `x` и идут из 1 в `n`. Каждый медведь —
единица потока; ребро ёмкости `c` может пропустить не больше `⌊c / x⌋`
медведей.

**Проверка для фиксированного `x`.** Строим ту же сеть, что в задаче, но
с пропускными способностями `⌊c_i / x⌋` и запускаем max-flow из 1 в `n`.
Если поток `≥ b` — такой груз возможен.

**Бинпоиск.** Функция «поток ≥ b» монотонно убывает по `x`
(больше груз — меньше ёмкости). Границы: `lo = 0`,
`hi = max(c_i) / 1`, 100 итераций дают точность лучше `1e-9`.

Сложность `O(iter · flow)`. Ловушки: делить ёмкости без округления вниз
(получится «дробный медведь»); и путать, что одинаково у медведей
(груз, а не маршрут — маршруты у них разные).

## F. Petya and Graph (1082G)

Доход — веса выбранных рёбер, расход — веса вершин, которые эти рёбра
задевают. Это maximum weight closure:

```
исток → (узел ребра e) : w_e
(узел ребра e) → (обе его вершины) : ∞
(вершина v) → сток : a_v
```

Если узел ребра остался на стороне истока, обе вершины обязаны быть там же
(иначе `∞`), и мы платим `a_v`. Если узел ушёл к стоку — теряем `w_e`.

Ответ `Σ w_e − mincut`. Сложность `O(flow)`. Ловушка: попытаться выбрать
вершины независимо от рёбер — тогда задача перестаёт быть корректной.

## G. Biologist (311E)

`n` животных, у каждого пол и стоимость смены. Есть требования «все из
набора — самцы» или «все — самки», с премией за выполнение и штрафом
за нарушение.

Модель разреза: сторона истока — «самец», сторона стока — «самка».

- если животное сейчас самец — ребро `исток → v` веса «стоимость сделать
  самкой»; если самка — `v → сток` веса «стоимость сделать самцом»;
- требование «все самцы» — узел `r`: `исток → r` веса премии и `r → v`
  с `∞` для всех животных набора;
- требование «все самки» — зеркально: `r → сток` и `v → r`.

Ответ `Σ премий − mincut`. Сложность `O(flow)`.

Ловушка: штраф за нарушение — это потерянная премия; прибавляйте его
к весу ребра премии, а не заводите отдельное ребро.

## H. Card Game (808F)

Нужен минимальный уровень персонажа, при котором можно собрать колоду
суммарного могущества не меньше `k`, где нельзя брать две карты с простой
суммой магических чисел.

**Бинпоиск по уровню.** Если колода собирается при уровне `L`, то и при
большем собирается (карт становится больше). Значит ищем минимальный `L`
от 1 до `n`; если и при `n` не хватает — ответ `-1`.

**Задача при фиксированном `L`.** Берём карты с `l_i ≤ L` и ищем подмножество
максимального суммарного могущества без «конфликтных» пар. Это maximum
weight independent set.

Конфликт — «сумма магических чисел проста». Разберём чётности:

- чётное + чётное ≥ 4 и чётно — не простое;
- нечётное + нечётное чётно и простое только при сумме 2, то есть `1 + 1`;
- значит все «нормальные» конфликты — только между нечётными и чётными.

Отсюда граф конфликтов двудольный (нечётные / чётные), а MWIS в двудольном
графе — это `Σ весов − min vertex cover`, то есть `Σ весов − max flow`:

```
исток → (нечётная карта) : p_i
(нечётная) → (чётная) при простой сумме : ∞
(чётная) → сток : p_i
```

**Случай `c = 1`.** Такие карты конфликтуют друг с другом (`1 + 1 = 2`),
значит взять можно не больше одной. Перебираем два варианта:

1. взять лучшую (максимальное `p`) карту с `c = 1`, остальные такие карты
   выбросить;
2. не брать ни одной карты с `c = 1`.

Для каждого считаем MWIS и берём максимум.

Сложность: `O(log n)` прогонов потока на графе из ≤ 102 вершин — мгновенно.

Ловушки: забыть про особенность `c = 1` (тогда граф перестаёт быть
двудольным и ответ завышается) и брать карты без учёта `l_i ≤ L`.
