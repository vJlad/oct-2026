# 06. Потоки — разборы

## A. Flawed Flow (269C)

Даны неориентированные рёбра и для каждой вершины (кроме стока) — требуемый
суммарный выходящий поток. Нужно сориентировать рёбра. Сумма требований
согласована с числом рёбер, поэтому ответ существует.

Поток считать не нужно. Идём от стока `n`: для каждого ещё не
сориентированного ребра направляем его «в сторону уже обработанной
вершины», то есть из второго конца в первый, и прибавляем его к счётчику
выходящего потока второго конца. Когда у вершины счётчик сравнялся
с требуемым — кладём её в очередь.

Почему работает: каждое ребро должно нести поток «к стоку», а суммарный
выход вершины задан; ориентация «к обработанной» — единственная
возможная, и условие на сумму гарантирует, что счётчик не переполнится.

Сложность `O(n + m)`. Ловушка: пытаться запускать max-flow — он тут
не нужен и не влезет по времени на плотных тестах.

## B. Array and Operations (498C)

Дано `n` чисел и `m` пар `(i, j)` с нечётной суммой индексов. Операция:
выбрать пару и поделить оба числа на общий простой делитель. Максимизировать
число операций.

Индексы разбиваются на чётные и нечётные — граф пар двудольный. Задача
распадается по простым: для каждого `p` считаем степени `e_i` в числах
и строим сеть

```
исток → (нечётные i) : e_i
(нечётные i) → (чётные j) по парам : ∞
(чётные j) → сток : e_j
```

Максимальный поток для `p` — сколько операций можно сделать с этим простым.
Ответ — сумма по всем `p`, встречающимся в числах.

Сложность: `O(ω · flow)`, где `ω` — число различных простых, все они
маленькие (факторизация до `10^9` пробным делением до `31623`).
Ловушка: строить одну сеть на все простые (нельзя — поток «смешает»
делители).

## C. Delivery Bears (653D)

`b` медведей несут одинаковый груз `x`, идут из 1 в `n` по путям.
Через ребро с пропускной способностью `c` проходит не больше
`⌊c / x⌋` медведей.

Бинпоиск по `x`. Проверка: строим сеть с пропускными способностями
`⌊c_i / x⌋` и запускаем max-flow из 1 в `n`; нужно `flow ≥ b`.

Верхняя граница — `max c_i`, точность `1e-6` (100 итераций).
Сложность `O(iter · flow)`. Ловушка: делить груз, а не пропускные
способности, и забыть округление вниз.

## D. Petya and Graph (1082G)

Нужно выбрать подмножество рёбер и подмножество вершин: доход — веса
рёбер, расход — веса вершин, которые задетых рёбрами.

Это maximum weight closure. Строим сеть:

```
исток → (узел ребра e) : w_e
(узел ребра e) → (обе его вершины) : ∞
(вершина v) → сток : a_v
```

Разрез: если узел ребра остался на стороне истока, то обе его вершины
тоже обязаны быть там (иначе `∞`), и мы платим `a_v`. Если узел ребра
ушёл к стоку — теряем `w_e`.

Ответ: `Σ w_e − mincut`. Сложность `O(flow)` на графе из `n + m` вершин.
Ловушка: забыть, что вершины без выбранных рёбер платить не должны
(в этой модели они автоматически уходят к стоку только если их ребро
не выбрано... поэтому веса вершин добавляются один раз, а не за каждое
ребро).

## E. Biologist (311E)

`n` животных, у каждого пол и стоимость смены. Есть требования:
«все животные из набора — самцы» или «все — самки», за выполнение — премия,
за нарушение — штраф.

Стандартная модель минимального разреза:

- сторона истока = «самец», сторона стока = «самка»;
- если животное сейчас самец, ребро `исток → v` веса «стоимость сделать
  самкой»; если самка — ребро `v → сток` веса «стоимость сделать самцом»;
- требование «все самцы» — узел `r` с `исток → r` веса премии
  и `r → v` веса `∞` для всех животных из набора;
- требование «все самки» — узел `r` с `r → сток` веса премии
  и `v → r` веса `∞`.

Ответ: `Σ премий − mincut`. Сложность `O(flow)`.

Ловушка: штраф за нарушение требования моделируется как «премия, которую
теряем», и его надо прибавить к весу соответствующего ребра, а не заводить
отдельное ребро.
