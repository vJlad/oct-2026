# 00. Welcome Round — разборы

## A. Сбалансированный массив (1343B)

Обозначим `k = n/2`. Первая половина — чётные `2, 4, ..., 2k`, их сумма
`k(k+1)`. Вторая половина: нечётные `1, 3, ..., 2k-3` (это `k-1` число,
сумма `(k-1)^2`) и последний элемент `3k-1`. Проверка:
`(k-1)^2 + 3k - 1 = k^2 + k` — совпало.

Осталось потребовать, чтобы `3k-1` было нечётным, то есть `k` чётное.
Если `k` нечётно (`n ≡ 2 mod 4`) — ответа нет: сумма нечётного количества
нечётных чисел нечётна, а сумма чётных чисел всегда чётна.

Сложность: `O(n)`. Ловушка: забыть случай `n = 2`, где первая половина
из одного элемента проходит, а вторая — нет.

## B. Игра на палиндроме, простая версия (1527B1)

Палиндром, значит нули стоят парами, и только центральный (если `n` нечётно)
может быть одиночным. Пусть `z` — количество нулей.

- `z = 1`: Алиса обязана перевернуть центральный ноль, платит 1, игра
  закончена — выиграл Боб.
- `z` чётно: Алиса портит палиндром, Боб сразу разворачивает строку
  (бесплатно) и возвращает Алисе ту же позицию. Каждый ноль в итоге стоит
  Алисе, Боб не платит — выигрывает Боб.
- `z` нечётно и `z > 1`: у Алисы есть ход, ломающий симметрию так, что
  «бесплатный разворот» больше не спасает, — выигрывает Алиса.

Ответ: `ALICE` при нечётном `z > 1`, иначе `BOB`. Сложность `O(n)`.

## C. Праздник (115A)

Начальник и подчинённый имеют разную глубину, поэтому в одну группу можно
собрать всех сотрудников одной глубины. Меньше ответить нельзя: цепочка
от корня до самого глубокого сотрудника обязана разойтись по разным группам.

Ответ — максимальная глубина в лесу. Считается обходом в глубину от корней
(`p_i = -1`) или «подъёмом» от каждой вершины к корню.

Сложность `O(n)` при мемоизации. Ловушка: наивный подъём без мемоизации
даёт `O(n^2)` — на `n = 2000` проходит, но это плохая привычка.

## D. Каникулы (698A)

ДП по последнему занятию. `dp[i][0]` — минимум отдыха, если день `i`
отдыхали; `dp[i][1]` — писали контест; `dp[i][2]` — занимались спортом.

Переходы: в состояние 0 можно прийти из любого; в состояние 1 — если
в день `i` есть контест (`a_i ∈ {1,3}`) и предыдущее состояние не 1;
в состояние 2 — если открыт зал (`a_i ∈ {2,3}`) и предыдущее не 2.

Ответ: `min(dp[n][*])`. Сложность `O(n)`.

## E. Максимальная медиана (1201C)

Ответ монотонен: подняв медиану до `x`, можно поднять её до любого меньшего
значения. Бинпоиск по `x`.

Проверка: отсортировать массив. Элементы левее позиции `n/2` на медиану
не влияют. Для `i ≥ n/2` считаем `cost = Σ max(0, x - a[i])`; условие —
`cost ≤ k`. Верхняя граница — `a[n/2] + k`.

Сложность `O(n log n + n log k)`. Ловушка: поднимать только `a[n/2]` —
элементы справа «перевесят» медиану вниз.

## F. Путешествие (839C)

Мат. ожидание длины пути = сумма по рёбрам вероятностей пройти по ребру
(линейность ожидания).

Пусть `p[v]` — вероятность когда-либо попасть в `v`. Для корня `p = 1`,
для ребра `u → v` при `u ≠ root`: `p[v] = p[u] / (deg(u) - 1)` — лошадь
выбирает равновероятно среди соседей, кроме того, откуда пришла.

Ответ — `Σ p[v]`. Удобно считать вклад при переходе:
`p[v] = p[u] / (deg(u) - (u != root))`.

Сложность `O(n)`, точности `double` достаточно.

## G. Ксюша и битовые операции (339D)

Удобнее всего — дерево отрезков, где операция зависит от уровня: листья
хранят элементы, их родители считают `OR`, следующие — `XOR`, и так далее
до корня. При `2^n ≤ 131072` дерево строится за `O(2^n)`.

При обновлении меняем лист и поднимаемся к корню, на каждом шаге применяя
операцию уровня. Ответ — в корне.

Сложность `O(2^n + m log 2^n)`. Ловушка: определить, какая операция
на каком уровне (считать от листьев, а не от корня).

## H. Шоколадный заяц (1407C)

Ключевое наблюдение: если `a < b`, то `a mod b = a`, а `b mod a < a`.
Значит из двух запросов `(x, y)` и `(y, x)` больший ответ — это значение
меньшего из двух чисел.

Алгоритм: поддерживаем индекс `mx` текущего максимума. Для `i = 2..n`
спрашиваем `q1 = p[mx] mod p[i]` и `q2 = p[i] mod p[mx]`.
Если `q1 > q2`, то `p[mx] = q1` и максимум переезжает в `i`; иначе `p[i] = q2`.
После цикла в `mx` лежит `n`.

Запросов `2(n-1) ≤ 2n`. Ловушка: не забыть `flush` и завершиться
по ответу `-1`.

## I. Game With Array (1355D) — новая

Идея: сделать так, чтобы суммы подотрезков принимали мало значений.
Возьмём `N-1` единицу и последний элемент `S-N+1`.

Тогда сумма любого подотрезка — это либо число из `[1, N-1]` (если большой
элемент не входит), либо число из `[S-N+1, S]` (если входит).

Возьмём `K = N`. Нужно, чтобы ни `K`, ни `S-K` не были суммами подотрезков:
`N` не лежит в `[1, N-1]`, а в `[S-N+1, S]` попадёт только если
`S-N+1 ≤ N`, то есть `S ≤ 2N-1`. Значит при `S ≥ 2N` всё хорошо.
Если `S < 2N`, то при любом массиве из `N` положительных чисел суммы
подотрезков покрывают слишком плотный диапазон, и подходящего `K` нет.

Сложность `O(N)`. Ловушка: граница `S ≥ 2N` (а не `S > 2N`).

## J. Ghosts (975D) — новая

В момент съёмки все точки лежат на прямой `y = a x + b`. Два призрака
встречаются, если существует момент `t`, когда совпали обе координаты.

Из `x_i + Vx_i t = x_j + Vx_j t` и такого же равенства по `y` (с учётом
`y = a x + b`) получаем: встреча возможна тогда и только тогда, когда
`Vy_i - a·Vx_i = Vy_j - a·Vx_j`.

Но если при этом `Vx_i = Vx_j` (а значит и `Vy_i = Vy_j`), призраки летят
параллельно и никогда не встретятся — такие пары надо исключить.

Итог: `answer = Σ C(cnt, 2)` по группам с одинаковым `Vy - a·Vx`
минус `Σ C(cnt, 2)` по группам с одинаковой парой `(Vx, Vy)`.

Сложность `O(n)` с хэш-таблицей (`O(n log n)` с сортировкой).
Ловушка: `a·Vx` до `1e18` — нужен 64-битный тип; ответ до `~2·10^10`.
